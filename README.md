# Double Link Inverted Pendulum Control Simulation

This project simulates and controls a **double link inverted pendulum on a cart** using **MATLAB** and **Simulink**.

The project focuses on nonlinear simulation, optimized swing-up trajectory tracking, upright stabilization, actuator saturation, actuator delay, sensor noise, robustness testing, Simulink validation, result evaluation, and optional Python visualization.

The main controller combines **optimized trajectory tracking using discrete Time-Varying LQR (TVLQR)** with a hybrid control structure for handoff and stabilization around the upright position. Python is only used as an optional tool to visualize and analyze result files generated by MATLAB/Simulink.

## State, Input, and Control Law

```text
State vector:
X = [x; x_dot; theta1; theta1_dot; theta2; theta2_dot]

Input:
u = horizontal force applied to the cart

Angle convention:
theta = 0  means pendulum downward
theta = pi means pendulum upright

Trajectory tracking control law:
u_cmd(k) = u_ff(k) - K(k)*e(k)

where:
u_ff(k) = optimized feedforward force
K(k)    = discrete TVLQR feedback gain
e(k)    = wrapped state tracking error

Actuator model:
F_actual is generated from F_cmd using a stable first-order discrete actuator model.

Hybrid control sequence:
trajectory tracking
-> handoff
-> terminal hold / stabilization
-> recovery or failsafe if needed
```

### Monte Carlo Failure Types

| Failure type | Meaning |
|---|---|
| tracking_not_in_handoff_gate | The tracker did not bring the system into the handoff region |

## How to Run

Open MATLAB and set the current folder to the project root.

Example:

```text
E:\BackupDown\Double_Link_Pendulum_Current
```

Configure the MATLAB path:

```matlab
run('matlab/startup_project.m')
```

Run the main TVLQR tracking test:

```matlab
run('matlab/simulation/run_tvlqr_tracking_test.m')
```

Expected output:

```text
phase29_pass = 1
Phase 29 run_phase29_clean_test: PASS
```

Run the full hybrid MATLAB controller:

```matlab
run('matlab/simulation/run_full_hybrid_matlab.m')
```

Expected output:

```text
phase30_pass = 1
Phase 30 run_full_hybrid_matlab: PASS
```

Run the Monte Carlo robustness test:

```matlab
phase31_profile = 'standard';
phase31_num_runs = 30;
run('matlab/simulation/run_monte_carlo_robustness.m')
```

Expected output:

```text
phase31_success_rate = 0.7
Phase 31 run_monte_carlo_robustness: PASS
```

Create and run the Simulink model:

```matlab
run('matlab/simulink/init_simulink_model.m')
run('matlab/simulink/run_simulink_test.m')
```

Expected output:

```text
phase32_pass = 1
Phase 32 run_simulink_test: PASS
```

Run the full evaluation summary:

```matlab
phase33_force_rerun = false;
run('matlab/evaluation/evaluate_all_scenarios.m')
```

Expected output:

```text
phase33_pass = 1
Phase 33 evaluate_all_scenarios: PASS
```

Run the optional Python visualization extension:

```bash
python -m python_extension.run_phase35_extension_demo
```

Expected output:

```text

```

## Limitations

This project is a simulation study. It does not include hardware implementation.

The current version includes nonlinear simulation, trajectory tracking, actuator delay, sensor noise, Monte Carlo testing, and Simulink validation. However, it still has several limitations:

- The optimized trajectory is designed for the selected upright target.
- The controller is not guaranteed to work under very large parameter uncertainty.
- Some Monte Carlo cases still fail after handoff or during stabilization.
- The stabilization logic can be improved for more difficult post-handoff states.
- Simulink validation is focused on the main successful control scenario.
- Python is only used for visualization and analysis of MATLAB/Simulink results.
- There is no hardware-in-the-loop or real-time deployment yet.
